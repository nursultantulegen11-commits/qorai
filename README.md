# QorAI

Склад и закупки для кафе и магазинов Тараза. Команда QorAI, Idea Battle 2026.

Next.js на Node.js, PostgreSQL и собственные аккаунты с входом по email и паролю. Приложение можно разместить в Render или на своём сервере через Docker.

## Возможности

- Приходы, продажи, списания и учёт партий со сроками годности.
- Текстовый разбор закупки: `Молоко 20 л по 450`. Работает без внешнего API.
- Фото накладной, голос и свободные вопросы через Gemini после настройки серверного ключа.
- Проверка распознанных позиций владельцем перед сохранением.
- План закупок из истории продаж, срока доставки и минимального запаса.
- Поставщики: имя, компания, контакт, телефон, Telegram и условия доставки.
- Черновик заказа с переходом в WhatsApp или Telegram. Сообщение отправляет пользователь.
- Личный склад каждого аккаунта, сохранение в PostgreSQL и контроль одновременных изменений.
- Адаптивный интерфейс, PWA, CSV и JSON, восстановление резервной копии в пустой склад.
- Гостевая демонстрация без регистрации. Учебные изменения действуют до обновления страницы.
- Презентация проекта по `/pitch`.

## Локальный запуск

Требуются Node.js 24 и PostgreSQL 15 или новее.

```bash
npm ci
cp .env.example .env.local
```

Укажите в `.env.local` строку подключения `DATABASE_URL` и `APP_URL=http://localhost:3000`.

```bash
npm run db:migrate
npm run dev
```

Для production:

```bash
npm run build
npm start
```

`npm start` сначала применяет миграции, затем запускает самостоятельный Node.js-сервер. Для публичного домена нужен HTTPS и соответствующий `APP_URL`. Render автоматически предоставляет адрес сервиса через `RENDER_EXTERNAL_URL`.

## Docker

```bash
cp .env.example .env
```

Замените `POSTGRES_PASSWORD` на случайный пароль из букв и цифр. Для локального запуска оставьте `APP_URL=http://localhost:3000`.

```bash
docker compose up -d --build
```

Откройте `http://localhost:3000`. База данных находится в отдельном томе, её порт не публикуется. Для домена с HTTPS предусмотрен профиль Caddy, инструкции находятся в [DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Авторизация

Регистрация и вход используют email и пароль. Пароли хранятся в виде scrypt-хешей с индивидуальной солью. Токены сессий случайные, в базе хранится только их SHA-256-хеш. Cookie имеет `HttpOnly`, `SameSite=Lax`, а на HTTPS — `Secure` и префикс `__Host-`. Сервер проверяет срок сессии и источник каждого изменяющего запроса.

Выход отзывает сессию в базе. Смена пароля завершает остальные сессии и выдаёт текущему браузеру новый токен. Попытки входа ограничиваются счётчиком в PostgreSQL. Публичные заголовки запроса не определяют владельца склада.

Минимальная длина пароля — 15 символов. Подтверждение email и восстановление пароля по почте пока не настроены.

## Данные

Все складские операции атомарны. Версия записи предотвращает потерю параллельных изменений, повторный идентификатор запроса не создаёт второй приход. Продажи расходуют пригодные партии с ближайшим сроком годности.

Экспорт JSON содержит товары, партии, историю и поставщиков. В настройках можно загрузить экспорт в пустой склад. Сервер проверяет структуру файла, ссылки на товары и числовые значения. Импорт не перезаписывает заполненный склад и не меняет владельца аккаунта.

## Настройка ИИ

Создайте серверный ключ в Google AI Studio и задайте `GEMINI_API_KEY` в окружении сервера. Не добавляйте его в Git или клиентский код. `GEMINI_MODEL` по умолчанию равен `gemini-2.5-flash`; доступность модели зависит от аккаунта Google.

Без ключа доступны склад, поставщики, текстовый ввод по шаблону и расчётные рекомендации. Содержимое фото и аудио передаётся Google после загрузки пользователем. Оригинальные файлы не сохраняются.

## Проверки

```bash
npm run typecheck
npm test
npm run build
npm start
```

В другом терминале:

```bash
QORAI_TEST_URL=http://localhost:3000 npm run test:api
```

Для этих тестов `APP_URL` сервера должен совпадать с адресом в `QORAI_TEST_URL`. Интеграционные тесты работают только с loopback-адресом и создают отдельные тестовые аккаунты. GitHub Actions запускает проверки с отдельным PostgreSQL.

## Ограничения MVP

Один склад на аккаунт. Кассовые интеграции, роли сотрудников и платежи не реализованы. Работы без сети с последующей синхронизацией нет. Максимум 200 поставщиков, 2000 товаров, 10000 партий и 20000 операций на аккаунт.

Прогноз использует до 28 дней продаж и простую формулу. Коэффициенты выходных и погоды являются гипотезой, а не обученной моделью. Экономия и готовность платить ещё не измерены. Цена 9900 ₸ за точку и три пилотные точки остаются планом для проверки.

Бесплатный Render предназначен для демонстрации: веб-сервис засыпает без запросов, бесплатная база истекает через 30 дней. Для постоянной работы нужен подходящий тариф и настроенные резервные копии. Измеренный SLA 24/7 не заявляется.
