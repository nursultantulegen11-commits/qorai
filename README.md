# QorAI

Full-stack MVP для кафе и магазинов Тараза. Команда QorAI, Idea Battle 2026.

## Возможности

- Учёт партий товара, приходы, продажи, списания, сроки годности и минимальные остатки.
- Обязательная проверка распознанной закупки перед сохранением.
- Текстовый разбор закупки без внешнего API: `Молоко 20 л по 450`.
- Gemini: фото накладных, аудио и свободные вопросы после подключения нового серверного ключа.
- Расчёт закупок из истории продаж, срока поставки и запаса. Условные коэффициенты на выходные и погоду.
- Погода Тараза из Open-Meteo с обработкой недоступности.
- Разделение складов по аккаунтам, атомарное сохранение, контроль ревизий и идентификаторы повторных запросов.
- Установка как PWA, интерфейс для смартфона и компьютера, CSV и JSON экспорт.
- Поставщики: имя или компания, контактное лицо, телефон, Telegram, категории и заметки.
- Черновик заказа из плана закупок, редактирование текста, открытие WhatsApp или Telegram. Сообщение отправляет пользователь в мессенджере.
- Публичный гостевой деморежим. Реальный склад и контакты поставщиков доступны только после входа и хранятся отдельно для каждого аккаунта.
- Встроенные SVG-иконки и локальные шрифты, карточки товаров и операций для телефона.
- Демосклад включается явно. Демоданные не являются реальными клиентскими данными.
- Презентация в браузере по `/pitch`.

## Стек

TypeScript, React, Vinext/Vite, Cloudflare Workers, D1 (SQLite), Drizzle. Хостинг через Sites, авторизация через платформенный вход ChatGPT. Аккаунт пользователя определяет платформа через доверенные заголовки, а не клиентский JSON.

## Локальный запуск

Требуется Node.js >=22.13.0.

```bash
npm ci
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_parched_skin.sql
npm run dev -- --port 5173
```

Откройте URL, напечатанный сервером. Локальный вход симулируется только на loopback. Production-сборка не содержит этот вход. Не выставляйте dev-сервер в интернет.

### ИИ

Создайте новый ключ в Google AI Studio. Ранее опубликованный ключ отзовите. Для локальной разработки сохраните `GEMINI_API_KEY` и необязательный `GEMINI_MODEL` в игнорируемом `.dev.vars`. Скопируйте имена переменных из `.env.example`. Для публикации настройте серверный секрет через Sites и повторно разверните версию. Ключ не должен попадать в браузер, Git или manifest.

По умолчанию модель `gemini-2.5-flash`. Её доступность зависит от аккаунта Google. Замените `GEMINI_MODEL`, если эта модель недоступна. ИИ не проверен живым запросом без нового ключа. Обработка накладных передаёт содержимое Google, об этом нужно уведомить будущих пользователей перед реальным пилотом.

## Публикация и работа 24/7

Sites публикует Worker и применяет миграцию D1. `.openai/hosting.json` содержит идентификатор конкретного Site. Для создания независимого Site из копии проекта сначала удалите только `project_id`, затем зарегистрируйте новый Site. Публичный Site открывает гостевое демо без входа. Его изменения существуют только до обновления страницы. Чтобы сохранять собственный склад и поставщиков, посетитель входит в аккаунт. Запросы к приватным данным и операции записи требуют серверной авторизации. Для принудительного просмотра демо даже после входа используйте `/?demo=1`.

После публикации сайт работает на инфраструктуре хостинга, независимо от ноутбука. `/api/health` проверяет базу, но на приватном Site внешний мониторинг требует платформенного доступа. Заявление о 24/7 не является измеренным SLA. Перед коммерческим запуском нужны нагрузочные испытания, внешнее наблюдение, автоматические резервные копии и проверка восстановления.

## Как устроен прогноз

Средний дневной спрос = сумма продаж за последние 28 дней / число дней наблюдения (от первой продажи, максимум 28). Горизонт = срок поставки + дни запаса. Выходные увеличивают дневной спрос на 15%. Погода применяется как приближение: жара >=25°C увеличивает спрос на отмеченные товары на 15%, холод <=10°C — на 10%. Используется текущий дневной максимум Тараза для всего горизонта, без обучения модели. Без погоды коэффициент равен 1. Эти коэффициенты требуют проверки пилотом. Без истории продаж используем только минимум владельца.

План = максимум из ожидаемого дефицита и дефицита до минимального остатка. Просроченный товар не считается пригодным остатком. Ближайшие сроки показываются отдельно. Бюджет ориентировочный, по последней закупочной цене, не выручка и не обещанная экономия.

## Ограничения MVP

- Один склад на аккаунт, без ролей сотрудников, кассовой интеграции и платежей.
- По товарам с разными названиями нет автоматического объединения: проверяйте наименование перед приходом. Одно название и единица измерения объединяют товар.
- Распознавание может ошибаться. Не сохраняет изменения без подтверждения.
- Записи хранятся документом в D1. Контроль ревизий предотвращает потерю параллельных изменений. При конфликте интерфейс обновляет склад и просит повторить операцию.
- Повторы дедуплицируются по последним 2000 идентификаторам запросов.
- Максимум 200 поставщиков, 2000 товаров, 10000 партий, 20000 операций на склад. Для большего объёма нужна нормализованная схема и архивирование.
- JSON является экспортом для резервной копии. Восстановление через UI пока не реализовано.
- Оригиналы фото и аудио не сохраняются. Нет офлайн-изменений, кеширования данных склада и фоновой синхронизации.
- Работоспособность интерфейса проверяется в доступных браузерах. Настоящие iPhone/Android устройства, разрешение микрофона и установка PWA требуют отдельной проверки.
