# Развёртывание QorAI

## Render

Создайте PostgreSQL и Node.js Web Service в одном регионе. Файл `render.yaml` описывает бесплатную конфигурацию для демонстрации.

- Репозиторий: `https://github.com/nursultantulegen11-commits/qorai`
- Ветка: `main`
- Регион: Frankfurt
- Node.js: 24
- Build Command: `npm ci --include=dev && npm run build`
- Start Command: `npm start`
- Health Check: `/api/health`
- `DATABASE_URL`: внутренний адрес PostgreSQL из панели Render.
- `TRUST_PROXY=1`.
- `NEXT_TELEMETRY_DISABLED=1`.
- `GEMINI_API_KEY`: необязательный серверный секрет.

Обычный адрес `onrender.com` приложение определяет через `RENDER_EXTERNAL_URL`. Для собственного домена задайте полный `APP_URL=https://ваш-домен` и добавьте домен в Render. Не указывайте ключи и строку подключения в репозитории.

При использовании публичного Git URL обновления запускаются вручную из панели сервиса. Подключение Git-провайдера или Blueprint позволяет настроить автоматическое развёртывание.

Бесплатный web-сервис засыпает через 15 минут без запросов. Бесплатный PostgreSQL действует 30 дней. Для постоянного бизнеса выберите тариф без этих ограничений и проверьте резервирование и восстановление. [Условия бесплатного тарифа](https://render.com/docs/free).

## Свой сервер

Установите Docker и направьте DNS домена на сервер. Скопируйте `.env.example` в `.env`. Задайте случайный пароль из букв и цифр, `DOMAIN=ваш-домен` и `APP_URL=https://ваш-домен`.

```bash
docker compose --profile https up -d --build
```

Caddy получает сертификат и направляет HTTPS-запросы в приложение. Приложение слушает внутри Docker, прямой порт доступен только через loopback сервера. PostgreSQL не публикует порт наружу. Тома сохраняют базу и сертификаты после перезапуска контейнеров.

## Проверка после публикации

1. `/api/health` возвращает `status: ok` и `database: ok`.
2. На `/register` создаётся аккаунт, после входа открывается личный пустой склад.
3. Приход и поставщик сохраняются после обновления страницы.
4. Второй аккаунт видит собственный склад.
5. Выход завершает сессию, смена пароля отзывает старые сессии.
6. Гостевой режим `/?demo=1` не изменяет личный склад.

## Перенос и резервные копии

В исходном приложении откройте настройки и скачайте JSON-экспорт. В новом приложении создайте аккаунт и загрузите файл в настройках пустого склада. Проверьте товары, партии, историю и поставщиков.

Для полной копии PostgreSQL используйте `pg_dump` с форматом custom:

```bash
pg_dump "$DATABASE_URL" --format=custom --file=qorai-backup.dump
```

Храните дампы зашифрованно вне сервера приложения. Проверяйте восстановление в отдельную пустую тестовую базу. Дамп содержит аккаунты, хеши паролей и данные бизнеса, его нельзя публиковать в GitHub.

Для восстановления в новую базу:

```bash
pg_restore --no-owner --no-acl --dbname="$RESTORE_DATABASE_URL" qorai-backup.dump
```

Восстановление не запускайте поверх рабочей базы. Не удаляйте Docker-том `postgres_data`, если данные ещё нужны.
